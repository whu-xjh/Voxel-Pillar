# Voxel-Pillar 代码风格与结构统一实施方案

日期：2026-10-25  
审查基线：`fe7464c9a151835365d652011facdef19b7a9b56`

## 1. 目标、范围与执行原则

本轮目标是建立统一的代码规范和可检查的模块边界，使算法、ROS 输入输出、参数管理及运行结果各有明确归属，同时保持有效输入下的既有算法行为。

交付范围：

- 固化命名、排版、头文件、类型、注释及资源管理规范。
- 分离 Pillar、体素地图、状态估计、ROS 发布和文件输出职责。
- 收紧公开可写状态，封装单帧处理顺序和跨帧状态生命周期。
- 统一参数加载与校验、构建依赖、工具脚本和文档入口。
- 建立可复现的基线、模块测试及回放验收方法。

执行原则：

1. 先记录基线，再改变实现；每个阶段独立编译、独立验收、独立回滚。
2. 格式整理、符号改名、文件迁移、结构重构、缺陷修复分开提交。
3. 不在结构提交中修改公式、坐标量化、浮点精度、候选遍历/平分规则、点顺序、线程数或编译优化。
4. 不因统一命名批量修改 ROS 参数键、topic、frame ID、消息类型、节点名、可执行文件名和输出格式。
5. 不引入 ROS 2 迁移、新的通用框架、传感器插件系统或新的算法功能。
6. 本轮继续使用 C++17、catkin、Eigen 和 PCL；先证明当前支持环境，再调整工具链最低版本。
7. 只移动确有独立职责的代码；不以文件行数、类数量或“一函数一文件”作为完成标准。
8. 实施中发现的行为缺陷单独记录、复现和修复。不能把旧缺陷写入新的接口契约，也不能静默修复后声称重构完全等价。

## 3. 统一编码规范

### 3.1 命名和布局

| 对象 | 规范 | 示例 |
|---|---|---|
| 自有文件 | 小写下划线；头文件继续使用 `.h` | `imu_processor.h` |
| 类型 | 大驼峰，缩写作为单词 | `ImuProcessor`、`LidarMeasurement` |
| 函数 | 小驼峰，表达动作或查询 | `processFrame()`、`isInitialized()` |
| 局部变量、参数、普通数据结构字段 | 小写下划线 | `frame_timestamp` |
| 类的私有成员 | 小写下划线加尾部 `_` | `imu_buffer_` |
| 常量 | `k` 加大驼峰 | `kStateDimension` |
| 枚举 | `enum class`，显式保留已有数值 | `PointLabel::kRedundant` |
| 自有命名空间 | `voxel_pillar` | `voxel_pillar::PillarMap` |
| 测试文件 | 被测模块名加 `_test.cpp` | `pillar_map_test.cpp` |

- 使用两空格缩进，禁止 Tab；LF 换行；文件末尾保留换行。
- 左大括号换行；指针/引用符号靠变量；建议列宽 120。
- 固定格式工具版本；实际支持的配置字段在阶段 1 验证，避免不同版本产生反复格式变更。
- include 顺序为对应头文件、项目头文件、第三方头文件、标准库头文件，并分组排序。排序前补齐直接依赖，防止暴露传递依赖时混入其他修改。
- 使用带包名和相对路径的 include guard，例如 `VOXEL_PILLAR_CORE_STATE_H_`。
- 保留有明确数学含义的局部符号，如 `R`、`J`、`H`；说明坐标系和维度，不强制改成冗长名称。
- `Process2` 等名称按实际职责替换，不能只机械转为 `process2`。

### 3.2 类型、接口与注释

- 头文件禁止 `using namespace std/Eigen`；使用完整限定名或窄范围类型别名。
- 用 `using` 表达别名；数值常量用 `constexpr`；固定维度矩阵宏逐步替换为别名模板。
- 宏替换时保留原数值类型、求值次数和运算顺序；PCL/Eigen 注册、对齐宏保留。
- 小型标量按值传参；大型只读输入用 `const&`；输出参数在命名或接口说明中明确。
- 纯数据结构允许公开字段；含不变量、缓存和生命周期的类默认私有成员。
- 不为收紧访问控制批量增加逐字段 setter；优先设计完成一项业务操作的接口。
- 注释说明前提、单位、坐标系、生命周期和算法原因。长算法说明放入 `docs/architecture.md`，代码保留定位入口与关键不变量。
- 对外头文件和代码注释优先英文，实施/实验文档可以中文；公式、参数名和文献术语保持一致。
- 无用的注释代码单独清理，不删除必要的推导依据和历史兼容说明。

### 3.3 不能顺手改动的类型约定

- 当前点类型为 `pcl::PointXYZINormal`，`curvature` 被用来存储扫描内相对时间，单位为毫秒；IMU 处理会转换为秒。
- 某些传感器分支复用 `normal_x/y/z` 存储颜色。先记录语义，不在本轮直接更换点布局或序列化格式。
- 坐标命名中的 body 在现有实现中可能指 LiDAR 坐标。接口文档须明确 LiDAR、IMU、world 的变换方向，不能仅靠改名推断。
- 自有代码改名不能改变 PCL 字段注册字符串、ROS 消息字段、枚举参数数值和 Eigen 对齐要求。
- `include/livox_ros_driver/CustomMsg.h`、`CustomPoint.h` 是生成文件，排除在格式、重命名和自有代码静态检查范围之外。其来源和再生成方式单独说明。

## 4. 目标结构和依赖方向

以下是最终目标，不要求在一次提交中建立所有目录和类。新增文件只有在相应职责迁入后才创建。

依赖规则：

1. `core`、配置值类型不能依赖节点、发布器和文件输出。
2. `pillar` 不依赖 `VoxelMapManager` 或 `StateEstimator`；接收点云和配置，产生标签、掩码和统计结果。
3. `mapping` 负责地图与估计；地图查询返回只读视图或值，写操作由串行主流程安排。
4. `pipeline` 组合 IMU、预处理、Pillar 和地图算法，持有明确的当前状态。
5. `ros` 负责参数服务、订阅、消息转换、发布与 TF；`io` 负责文件生命周期。
6. 可视化可以读取算法输出；算法不能反向依赖可视化。
7. 不要求第一阶段立即去除全部 `sensor_msgs` 依赖。先拆开头文件，再在阶段 5 将 ROS IMU 消息转换到内部测量结构，保留时间精度、缓存顺序和拷贝成本基线。
8. 不为依赖注入给所有类建立抽象基类；仅在存在实际替代实现或清晰测试边界时引入接口。

## 5. 必须保留的单帧流程与数据契约

### 5.1 当前主流程顺序

以 `LIVMapper::handleLIO()` 为基线，拆分时保持下列顺序：

1. 使用已完成 IMU 处理的状态和去畸变点云；记录原有预测状态日志。
2. 降采样；滤波尺寸为 0 时继续复制点云，避免后续删点修改原始去畸变点云。
3. 用当前预测状态将降采样点云转换到 world，并进行初始化窗口内的强度噪声估计。
4. 若启用 Pillar：建图 → 新点检测 → 更新历史 → 冗余/孤立检测 → 采样 → 生成删点掩码 → 可视化消费 → 清理临时状态 → 同步压缩两份点云。
5. 首帧在 Pillar 筛选之后建立初始体素地图；继续执行原有首帧状态估计流程。
6. 状态估计；更新高频 IMU 传播所需的状态快照；保存轨迹并发布里程计。
7. 使用更新后的状态重新变换点云、更新点协方差并更新地图；按原条件进行地图滑动。
8. 发布/保存最终点云，更新帧计数和耗时统计，记录估计后的状态。

不得因为接口更容易写而将 `UpdateHistory()` 移到 `DetectNewPoints()` 之前；检测需读取此前帧的窗口，而后续邻域检查的原有历史语义也要保留。

强度退化状态机本帧更新的锁存状态影响后续帧关联。拆分 `StateEstimator` 时要显式表达“本帧关联上下文”和“更新后的状态”，避免提前使用下一帧开关。

### 5.2 Pillar 生命周期

| 生命周期 | 代表数据 | 清理时机 |
|---|---|---|
| 单帧 | `pillars_`、标签、新点标记、采样结果、冗余体素指针 | 本帧消费者完成后清空；清空前不得压缩其引用的点云 |
| 可复用工作区 | `sample_ws_` 等 scratch buffer | 重置逻辑长度，尽量保留容量 |
| 跨帧 | 历史窗口、历史计数、动态缓冲、动态证据、帧编号 | 正常单帧清理时保留；显式重置会话时清空 |
| 独立结果 | 本帧删除掩码、统计、按需构造的可视化数据 | 消费完成后释放或复用；不得持有已清空体素的指针 |

建议分两步封装：

- 过渡阶段：原样封装处理顺序，将 `ClearPillarMapVoxels()` 改为 Pillar 自有的清理方法，暂时保留现有发布调用位置。
- 目标阶段：`processFrame()` 内完成算法处理并导出结果，ROS 层消费结果后再执行点云压缩。临时容器何时释放由 Pillar 自己负责，不向上层暴露内部容器。

接口草案（表达职责与所有权，不是可直接编译的完整实现）：

```cpp
struct PillarFrameResult
{
  std::vector<uint8_t> remove_mask;  // 索引对应删点前降采样点云
  PillarStatistics statistics;
  // 标签和可视化输出按消费者需要生成，不能默认复制整份点云。
};

class PillarMap
{
public:
  PillarFrameResult processFrame(const PointCloudXYZI& world_cloud,
                                const PillarOutputRequest& output_request);
  void resetSession();

private:
  void resetFrame();
  // 单帧数据、历史数据和工作区由本对象持有。
};
```

必须满足：

- 正常输入下 `body_cloud.size() == world_cloud.size() == remove_mask.size()`。
- 空点云、无删除、全删除均有明确返回；正常压缩保持保留点相对顺序及两份点云对应关系。
- 当前 `removeFlaggedPoints()` 以最短长度工作。改为严格长度检查属于独立输入校验修复，不能隐藏在移动代码的提交中。
- 原始点索引、标签和采样结果不能在压缩后按旧索引访问；诊断需要时在压缩前导出索引映射。
- 没有可视化消费者时不构造彩色点云，但不能因此停止算法需要的动态历史更新。显示桥接所需数据是否保存，保持原开关语义。
- 移动返回或复用缓冲区，禁止为“接口整洁”引入逐帧全量深拷贝。

## 6. 参数与兼容性实施规则

### 6.1 配置流

采用 `加载 → 兼容字段处理 → 校验/归一化 → 生效配置 → 构造模块`。ROS 读取函数放在 `parameter_loader.cpp`，配置结构体只保存值。

- 结构体完整初始化，并成为默认值的单一来源；加载器使用字段现值作为缺省值。
- 初始默认值以当前正式启动路径中加载器的实际值为准，例如 `lio/capacity` 缺失时保持 0，继续表示关闭容量限制。
- 先保留现有单份 YAML 的加载方式。全部键有清单后，再考虑公共默认文件加数据集覆盖；覆盖前后需逐键比较生效配置。
- 参数清单至少记录：ROS 键、C++ 字段、类型、单位、缺省值、范围、开关依赖、历史兼容行为。
- 原本会 clamp 的参数先保留 clamp 并记录警告；新增拒绝策略单独作为行为变更提交。
- 未识别参数仅在项目管理的配置分组内检查，不能把 ROS 参数服务器上的其他节点参数认作错误。

### 6.2 `keep_redundant` 的具体迁移

当前包含该键的文件：`avia.yaml`、`NTU_VIRAL.yaml`、`GEODE.yaml`、`merge_lidar.yaml`、`MARS_LVIG.yaml`。

实施方式：

1. 记录这些文件当前实际生效的 `delete_redundant=false`，不能根据字段字面含义自动取反。
2. 仓库内配置删除无效键，显式写入 `delete_redundant: false`，保持原有运行效果。
3. 对仓库外的旧配置，发现 `keep_redundant` 时警告其未参与当前算法；不静默映射。若同时存在新键，以新键为准。
4. 文档说明：此前 `keep_redundant` 未生效；需要删除冗余点的用户应显式设置新键，且 PRISM 采样启用时仍保持其原有优先级。
5. 该迁移不连带重命名 `redundant_GFH_*`、`dept_err` 等现有 ROS 键；内部字段可使用规范名称并建立显式映射。

> 注（2026-10-29）：`redundant_GFH_sample_*` 已更名为 `redundant_sample_*`（采样方法定名 PRISM）。上述"不连带重命名"仅记录该次迁移当时的决策，以当前仓库为准。

### 6.3 校验清单

| 参数/输入 | 要求 |
|---|---|
| LiDAR→IMU 外参 | T 长度为 3，R 长度为 9，元素有限；缺失时给出参数名并终止初始化，禁止索引空数组 |
| 外部 IMU 外参 | 启用外部 IMU 时必须有效；禁用时不索引缺失数组，可初始化内部单位变换 |
| 旋转矩阵 | 检查正交性和行列式；先用仓库内外参精度确定容差，不静默正交化 |
| 扫描线/抽样步长 | 步长为正；扫描线数量在对应传感器处理器及固定缓存支持范围内 |
| 体素尺寸 | 算法实际使用时为正；降采样尺寸单独处理，0 继续表示关闭降采样 |
| 层数/初始化阈值 | 层数非负，`layer_init_num` 至少覆盖根层到最大层，阈值满足现有算法前提 |
| 采样比例/bin | 比例、bin 有限；保留原有 clamp/回退规则并记录归一化后值 |
| 退化阈值 | 有限且 `off > on`，连续帧数为正 |
| 外部 IMU 模式 | `external_imu_only` 与 enable、缓存长度、初始化窗口的组合有明确检查 |
| 历史/容量哨兵 | 不能简单要求全部为正；保留 `pillar_buffer <= 0`、`capacity <= 1` 等当前约定 |
| 保存间隔 | 保留 `-1` 的原有语义，不以一般正数校验误伤合法配置 |

配置校验失败应在订阅、建图和创建运行结果文件之前返回清晰错误。禁用外部 IMU 时不要求提供无用外参属于明确的校验修复，应有测试。

### 8.2 结果比较规则

1. **先比较输入覆盖。** 每帧时间戳、处理帧数和同步后输入数量不同，不能继续用 ATE 相近证明等价。
2. **离散结果严格相等。** 标签、掩码、保留点顺序、对应平面身份、有效点数、状态机切换帧、体素数和淘汰数按适用阶段比较。
3. **浮点结果分层比较。** 固定环境的机械整理优先要求输出一致。结构重构比较每帧位置、旋转差、协方差、残差统计；相同测试输入下确认差异来源后才能接受数值容差。
4. **容差预先冻结。** 在阶段 0 的稳定基线建立绝对/相对误差阈值，并写入回归配置。可从位置/角度 `1e-9 m/rad`、矩阵元素 `atol=1e-10, rtol=1e-8` 开始评估，但这只是初始候选，不能宣称适用于所有数据、输出精度和平台。基线不能稳定达到时先排查输入及数值顺序，定稿后不得为让某次重构通过而临时放宽。
5. **保留足够精度。** 检查点内部状态用足够精度导出；低精度 TUM 文本无法证明更细的数值一致。旋转比较用相对旋转角，避免四元数正负号造成假差异；拒绝非有限值。
6. **不改变量化边界。** 增加正负整数体素边界及其两侧样本，覆盖历史量化规则；浮点容差不能放宽离散 voxel key 的差异。
7. **准确率是补充。** 有真值时报告 ATE/RPE 和对齐方式；无真值时只报告前后轨迹差，不能称为精度提升。
8. **修复另立基线。** 无效配置拒绝、实例隔离等明确行为修复单独列出允许差异，其余有效输入继续要求一致。

当前 `MP_PROC_NUM` 受编译定义控制，函数内又调用 `omp_set_num_threads()`；只设置 `OMP_NUM_THREADS=1` 不足以保证串行基线。若增加线程数配置，应独立提交并验证原缺省行为，或使用明确可控的回归构建。

### 8.3 性能与资源

- 固定 CPU、输入范围、编译选项、线程数、日志/保存开关及 RViz 订阅状态。
- 对同一配置至少运行 3 次，报告每帧总耗时与各阶段 p50/p95、峰值 RSS、处理帧数。基线波动大时先改善测量条件。
- 初始性能门槛建议为总耗时 p95 不恶化超过 5%、峰值 RSS 不增加超过 10%；阶段 0 根据测量噪声固定门槛。超限需说明原因及是否为明确接受的功能成本，不能直接忽略。
- 已知每帧处理路径检查新增分配和整云复制。除正常输出需要外，重构不应引入长期积累的缓存。
- ASan/UBSan 用于有资源或索引变化的模块测试和短回放；第三方库问题单独定位并记录，不能用性能构建代替。TSan 仅在工具链/依赖支持时辅助检查，不作为所有环境已通过的默认承诺。

### 8.4 每次提交的最小验证

| 提交类别 | 必须执行 |
|---|---|
| 纯文档 | 链接、路径、术语和任务状态核对 |
| 纯格式 | 格式检查、差异检查、编译 |
| 重命名/搬文件 | 全量编译、头文件检查、基础回归 |
| 配置 | 配置矩阵和预期差异测试、基础回归 |
| Pillar/估计/地图 | 受影响模块测试、相关开关回归、性能与资源检查 |
| 构建/依赖 | 干净构建、Debug/Release、依赖选项矩阵 |
| 输出/脚本 | 格式消费测试、路径测试及相关回放 |

构建和回放使用独立的可写输出目录；不把生成文件写回源码目录。具体 catkin 命令根据已记录的工作区工具填写到基线文档，不能混用 `catkin_make` 与 `catkin build` 的同一构建目录。

## 9. 与现有诊断实施方案的衔接

配套文件：[约束贡献与强度关联诊断实施方案](diagnostics_implementation_plan_zh.md)。

- 本方案不自动实施诊断功能。两份文档同时推进时，先完成阶段 0 和 Pillar 生命周期接口，再接诊断快照，避免在公开容器上增加新的跨模块写入。
- 诊断需要的删点前点标签、删除掩码和原始索引在压缩之前导出；标签不等于实际删除决定。
- 候选查询/观测线性化可以由地图与估计模块提供只读接口；诊断不得修改生产评分、LRU、强度 EMA、退化状态或 map 内容。
- 诊断默认关闭时继续遵守原方案的零额外数据复制/搜索/文件创建约束；不能借重构默认启用诊断收集。
- 保留原方案的 `ablation_information`、`ablation_out_path` 参数名及单 TXT 输出约定；路径迁移不改变功能含义。
- 所有实现方案引用的 `LIVMapper`、`voxel_map` 旧路径在阶段 8 统一更新，并给出新模块定位。

## 10. 提交组织、风险及回滚

### 10.1 建议提交边界

建议按以下顺序组织；单项过大时继续拆分，但每个中间提交都应可编译：

1. 基线、回归入口与环境记录。
2. 格式配置和检查入口。
3. 纯格式提交。
4. 符号命名、公共类型和自有命名空间（可拆多次）。
5. 参数加载提取；另一个提交处理校验和无效配置键。
6. Pillar 文件提取；另一个提交封装生命周期；再分离可视化。
7. 主流程、同步和输出模块提取；锁与静态状态治理单独提交。
8. 八叉树/地图提取；估计器提取；所有权治理分别提交。
9. CMake/依赖治理。
10. 脚本目录、README 和迁移文档收口。

PR 描述需包含：具体问题、改动后的行为、影响接口、保持的兼容项、测试结果、未验证环境和允许差异。格式变更与算法改动不能混在同一评审差异中。

### 10.2 风险与控制

| 风险 | 控制办法 | 回滚单位 |
|---|---|---|
| 历史窗口或强度开关错一帧 | 跨帧用例、记录开关生效帧 | 对应生命周期/上下文提交 |
| 删点后标签索引失效 | 固定原始索引、压缩前消费或快照、大小契约 | Pillar 结果接口提交 |
| 智能指针迁移造成配置悬空/迭代器失效 | 审核对象可移动性、借用关系、析构顺序 | 所有权提交 |
| 改容器/量化导致候选或边界变化 | 本轮冻结容器与量化规则，边界用例 | 地图提取提交 |
| 默认值归并改变实验开关 | 比较实际生效值，保留键与哨兵语义 | 配置迁移提交 |
| ROS 发布抽离改变时间戳/订阅行为 | 记录原时间源和订阅门控，明确消费者请求 | 可视化/输出提交 |
| 构建选项导致数值或性能变化 | 保留选项并对比 compile/link 命令 | 构建提交 |
| 移动文件破坏用户脚本或 launch | 旧入口兼容、路径检索、干净环境验证 | 工具和入口迁移提交 |

回滚流程：保存失败输入、配置和比较报告 → 定位首个失败提交 → 撤销该独立提交或其依赖链 → 在同一基线重跑相关用例。使用可审查的 revert，不使用强制重置覆盖用户工作。文件迁移只反向恢复路径，不删除实验结果或真值数据。

## 11. 最终完成标准与执行记录模板

全部完成需满足：

- [ ] 自有代码有统一命名、格式和检查入口，生成代码明确排除。
- [ ] `common_lib.h` 不再承担无边界依赖聚合；公开头文件能独立使用。
- [ ] 参数加载集中，默认值唯一，所有仓库配置有生效值校验和参数文档。
- [ ] Pillar 管理自身帧数据和历史，外部不直接清理或写其容器。
- [ ] 节点负责 ROS 接入；算法、地图、估计、可视化与文件输出的责任明确。
- [ ] 地图/八叉树资源所有权明确，可变运行状态按实例隔离。
- [ ] 原有 ROS 入口、外部参数及结果格式兼容，所有有意行为变化都有记录。
- [ ] 已声明支持环境完成干净构建；未覆盖平台/传感器明确列出。
- [ ] 受影响分支的回归、边界、资源和性能检查达到冻结的验收标准。
- [ ] README、架构、配置、回归和诊断文档使用最终路径与接口。

阶段记录使用如下模板，保存在 `docs/refactoring_progress.md`：

```text
阶段/提交：
实施起点提交：
类别：格式 / 命名 / 迁移 / 结构 / 修复 / 构建
改动文件和符号：
保持的外部接口：
有意行为差异及复现输入：
验证命令和环境：
数据标识、配置哈希、处理帧数：
离散结果比较：
浮点比较阈值与最大差异：
耗时/峰值内存对比（需要时）：
未验证项目与原因：
回滚方式：
阶段结论：待实施 / 实施中 / 已完成 / 验证受阻
```

首批可执行工作为阶段 0—1；首个结构收益目标为阶段 4 的 Pillar 职责和生命周期封装。后续拆分以实际依赖和验收证据推进，不以目录已经建好或代码已经搬完作为完成依据。
